## 项目模式与已整合成果

两个页面顶部均提供“真实空间模型 / 激光房间模拟”切换，“模型资料”可查看各自的功能和当前校正进度。

- **真实空间模型**：当前采用 `激光空间模拟v2.0.3dm`，源单位毫米，1591 个源物体、23 个图层。包含空间结构、激光路径、发射头、接收器、摄像机和反光板，默认显示全部图层。按源文件单位换算为米，保留 Z 轴向上、图层、物体名称及相对坐标。已有图层显隐、尺寸与高程查看、空间漫游、新版 `.3dm` 本地预览及查看配置导出。
- **激光房间模拟**：直接载入相同的完整v2.0 Rhino模型，使用原模型的空间结构、72个地面和72个墙面反光板、288条红绿光路以及实际相机机位，加入行走、光路和视线遮挡预演。

两个页面统一使用原模型坐标。模拟页面已替换早期参数阵列；相机位置从模型机位方块提取，方块中心暂代光心，实际镜头光心仍需标定。

两个页面均使用v2.0实际机位数据，支持现有6台/未来12台地面相机、3台墙面相机、横竖构图，以及墙面同吊点高度对照。地面按85°、墙面按120°理想视场计算；镜头标定前不能把预演高度当作最终施工尺寸。机位编号、俯角和计算依据见 [CAMERA_PLAN.md](CAMERA_PLAN.md)。

当前验收以6台、3区、每区最多1名玩家为准，目标是对72个地面红色光点做红色滤片＋黑白视频＋逐点ROI亮度检测，红光被遮断或切绿光均报警。12台是后续扩展方案。硬件亮度检测与玩家互遮挡测试尚未接入；几何预演通过不代表该验收已通过。

现有相机1080p、光斑约50mm；当前试验预算采用约480p、8fps、暂定200ms检出/响应目标。“现场摄像头预演→地面采集预算”可比较像素与采样等待，实际设备尚未配置。详细边界与优化方案见 [CAPTURE_PLAN.md](CAPTURE_PLAN.md)。

## 本地启动流程

需要 Node.js 22.12 或以上（含 npm）。在终端执行：

```sh
git clone https://github.com/dongfeng19830925-stack/laser-space.git
cd laser-space
npm ci
npm run dev
```

启动后保持终端运行，浏览器打开终端显示的地址（默认 `http://127.0.0.1:5173/`）：

- Rhino 模型查看器：`http://127.0.0.1:5173/`
- 激光房间模拟：`http://127.0.0.1:5173/laser-room/`

如果端口被占用，以终端实际显示的端口为准。按 `Ctrl+C` 停止服务。不要直接双击 HTML 文件启动。

生产构建和本地预览：

```sh
npm run build
npm run preview
```

预览默认地址为 `http://127.0.0.1:4173/`；模拟入口为 `/laser-room/`。构建输出在 `dist/`，两个页面会一同构建。

## 激光房间模拟（独立入口）

源码位于 `laser-room/`，使用与工作台相同的 `.3dm`。启动和构建时自动提取场景及机位，浏览器校验模型与派生数据的SHA-256一致后再显示。

- 保留Rhino毫米换算、Z轴向上、原结构和设备位置；12列反光板首尾跨度9.9m。
- 现有6台：G01/G04、G05/G08、G09/G12，各对相向观察同一组4列；未来12台各对观察2列。墙面W01–W03分别观察4列、排除最高一行。
- 相机XYZ使用模型坐标；仅调整观察方向。墙面下调默认0mm，滑杆用于同吊点竖直高度对照。默认地面85°、墙面120°，可比较水平/对角视场解释及横竖构图。
- 默认3名身高180cm的行人，各自在对应区域内独立变速、横移、停顿和往返；可切换4人自由行走压力对照，暂停、重置或手动定位P1。
- 总览显示真实场景，可将墙面半透明；摄像头画面始终保留实体深度遮挡。默认摄像头为黑底接收点滤光预演，关闭滤光选项后显示普通场景。
- 红绿光路按模型中的路径与颜色提取。人体遮断光路时对应模拟亮点熄灭，人体挡住视线时保留遮挡；切绿光时红色滤光画面中的点熄灭。亮点直径按用户估计的50mm表示。
- 监看画面默认8fps，仅控制预演刷新；多个画面共享一个WebGL渲染器，避免12台方案创建大量图形上下文。

操作：拖动旋转、滚轮缩放、右键或双指平移；底部切换总览、正视、房间内部与俯视；点击CAM标题放大。

**当前限制：** 未连接真实摄像头、激光或感光硬件。碰线提示来自模拟几何计算，不是视频识别。滤光视图仅为视觉近似，未标定真实波长、曝光、散射亮度；尚未实现真实ROI亮度检测或断光/视线遮挡分类。原模型机位方块中心暂代光心，镜头视场与畸变待实拍标定。行人使用简化人形与避让逻辑，不是人体测量或完整人群物理仿真。

关键文件：`laser-room/index.html`、`laser-room/src/main.js`、`laser-room/src/walkers.js`、`laser-room/src/style.css`。Three.js通过项目npm依赖打包，无需复制 `node_modules` 或第三方库源码。

## 更新模型

1. 在犀牛中继续修改原工程，明确设置文件单位，保留图层和设备物体名称。使用“着色”视图后保存，以保留渲染网格。
2. 运行 `npm run model:package -- "新版完整模型.3dm的路径" "新的Release标签"`，生成无损gzip分片及 `models/manifest.json`。输出目录在 `.local/model-release/<标签>/`。
3. 在同名GitHub Release上传全部 `.partNN` 分片和 `manifest.json`，完成发布后，再提交代码与清单。不要将完整 `.3dm` 或压缩包加入普通Git提交。
4. 按需要更新 `public/project.json` 中的模型名称和版本。运行 `npm run model:prepare`，自动下载、拼合、解压并核对SHA-256，生成本地 `public/models/space.3dm`；本地模型校验一致时直接复用。
5. 运行 `npm run build`，自动重新生成 `public/camera-plan.json` 与 `public/scene-layout.json`，检查后随代码一起提交并推送到 `main`。GitHub Actions 自动还原模型、提取数据并更新 GitHub Pages。若新模型改变了反光板图层、入口/出口标记、相机分组或光路结构，提取会报错，需要按新模型调整规则；浏览器遇到SHA-256不一致时拒绝混用旧数据。

### 大模型存储

完整模型使用GitHub Release分片保存，不使用Git LFS。仓库仅保存代码和 [模型清单](models/manifest.json)，每个分片不超过16MiB；分片、拼合后的gzip和解压后的原模型均有大小与SHA-256校验。当前v2.0原模型144,661,528字节，无损压缩为42,154,773字节，分为3片，几何、单位、图层和UUID不变。

首次启动/构建需要从Release下载，之后校验通过的本地模型可离线复用。Pages部署时还原普通 `.3dm` 文件，因此浏览器仍从同一网站加载，无需跨域读取Release资源。仓库中的旧模型已停止跟踪，本机生成文件被Git忽略。

网页的“打开新版模型”在本机解析选中的文件，不会上传或改动线上模型。这样可以在正式发布前检查新版。图层与查看设置按模型文件 SHA-256 隔离保存在当前浏览器，“保存查看配置”可以导出 JSON。

## 查看功能

- Three.js 原生 Rhino3dmLoader 读取缓存网格、曲线和块，保留相对坐标及图层信息。
- 毫米/厘米/米/英寸/英尺等单位转换为米，Z 轴向上。
- 空间、结构、布置、全部显示方案；逐层显隐；半透明墙面、轮廓线和原模型颜色。
- 透视、俯视、侧视，适配视图；点击选择，查看世界坐标包围盒尺寸与高程。
- 自由漫游：拖动环视，W/A/S/D 移动，Q/E 升降，Esc 退出。当前无碰撞约束。
- 手机和平板自适应布局。

## 继续编辑

- `src/main.js`：载入模型、图层、相机、选择与漫游逻辑。
- `src/style.css`：界面样式。
- `index.html`：界面结构。
- `public/project.json`：模型地址、名称与版本。
- `models/manifest.json`：当前模型Release地址、分片顺序和校验值。
- `scripts/prepare-model.mjs`：下载、拼合、还原并验证模型。
- `scripts/package-model-release.mjs`：为后续模型生成Release分片和清单。
- `scripts/generate-scene-layout.mjs`：从当前Rhino模型提取机位、反光板、红绿光路及入口方向；可单独运行 `npm run model:layout`。
- `public/camera-plan.json`、`public/scene-layout.json`：带源模型SHA-256的派生数据，两个页面共用机位数据。
- `public/models/space.3dm`：启动/构建时生成的当前工程模型，不加入Git。
- `.github/workflows/deploy.yml`：GitHub Pages 自动部署。

原模型中的文字、尺寸、引线和填充等施工注释不一定被 Three.js 转换；三维实体使用 Rhino 保存的渲染网格。需要完整工程信息时，请以 Rhino 原工程为准。模型文件会随站点部署，可被网站访问者下载。

当前两个页面均绑定同一份Rhino v2.0模型；拍摄方向按已确认的反光板分组计算，不能替代实际镜头标定和现场遮挡验收。
